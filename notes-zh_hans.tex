\section{概述}

本文档演示如何在您自己的计算机上运行一个小型语言模型。您还会使用 Pi\footnote{如果您听说过 OpenClaw，也就是“小龙虾”，Pi 是 OpenClaw 底层所依赖的工具。} 这个智能体命令行工具与模型交互。示例中使用 llama.cpp 来运行模型，并使用 Qwen3-0.6B 作为练习模型。

本教程的目标不是构建速度最快或能力最强的本地 AI 系统，而是学习通用工作流：安装工具、下载模型文件、启动本地模型服务器、将 Pi 这样的应用连接到这个模型服务器，并尝试一些任务。我们选择了一个小模型，所以本次工坊可以在大多数个人计算机上完成。

本文档分为两个主要部分。快速入门部分给出从准备运行环境到运行本地模型的最短路径。后面的章节更详细地解释工具、文件、命令和相关选择。

本文档开源在 GitHub 上，并在 MIT 协议下发布。\footnote{\url{https://github.com/codebar-shanghai/workshop-local-llm}}\footnote{\url{https://github.com/codebar-shanghai/workshop-local-llm/blob/main/LICENSE}} 请查看 GitHub 仓库获取本文档的最新版本。

\subsection{安装 Docker}

Docker 并非在本地运行语言模型的必需组件。我们在本次工坊中使用 Docker 来简化安装。一个 Docker 镜像就像是一个准备好的软件包，它包含了我们所需要的软件和设置，所以您不必手动安装每一项。

同时 Docker 可以将本次工坊使用的工具和您计算机系统上的其他文件隔离开。工坊结束后，您可以轻松地删除镜像和容器。在第 \ref{sec:llama.cpp} 节我们将介绍如何不依赖 Docker 设置运行环境。在第 \ref{sec:Docker} 节我们也将讨论为什么 Docker 可能依然有用。

官方指南：\url{https://docs.docker.com/desktop/setup/install/windows-install/}。

\item 安装 WSL。\footnote{WSL 是 Windows Subsystem for Linux 的缩写。它是 Windows 10 以及 11 的可选组件。在 Windows 上运行 Docker 依赖 WSL。本文中我们不会详细讨论 WSL，它超出了本次工坊的范畴。} 首先检查 WSL 是否已经安装。打开 PowerShell 或者\textbf{命令提示符}，然后输入这个命令：

\subsection{运行模型}
\label{sec:run-llama.cpp}

以下的命令被分为多行以便阅读。每一行结尾的 \texttt{\textbackslash} 表示下一行继续。您可以去掉这些 \texttt{\textbackslash} 字符，把命令写成一行。

如果您使用 Windows 系统并将模型文件存放在 \texttt{c:\textbackslash{}models} 文件夹中，使用这条命令。如果您使用了和示例不同的文件夹，请将 \texttt{c:\textbackslash{}models} 替换为正确的文件夹。

\begin{minted}{bash}
docker run --rm -it \
  -p 8080:8080 \
  -v "c:\models:/models" \
  ghcr.io/ggml-org/llama.cpp:server \
  -m /models/Qwen3-0.6B-UD-Q4_K_XL.gguf \
  -c 32768 \
  --port 8080
\end{minted}

如果您使用 Linux 或者 macOS，并将模型文件放在 \texttt{\$HOME/models}\footnote{\textbf{\texttt{\$HOME}} 代表您的个人主目录。}，请执行以下命令。如果您使用了和示例不同的文件夹存放模型文件，请将 \texttt{\$HOME/models} 替换为正确的文件夹。

\begin{minted}{bash}
docker run --rm -it \
  -p 8080:8080 \
  -v "$HOME/models:/models" \
  ghcr.io/ggml-org/llama.cpp:server \
  -m /models/Qwen3-0.6B-UD-Q4_K_XL.gguf \
  -c 32768 \
  --port 8080
\end{minted}

简单解释一下这个命令。\texttt{ghcr.io/ggml-org/llama.cpp:server} 是您刚刚导入的镜像。在它前面的选项作用于 \texttt{docker}。它后面的选项则作用于 \texttt{llama.cpp}。

\textbf{\texttt{docker}} 的选项：

\begin{itemize}
\item \texttt{-p} 将容器的端口发布到您的计算机上。\texttt{8080:8080} 中，冒号之前的数字表示您计算机上的端口，之后的数字表示容器内的端口。如果您计算机上的 \texttt{8080} 端口已被使用，可以尝试其他端口，例如 \texttt{8081}，那么这个选项应该写为 \texttt{-p \textbf{8081}:8080}。
\item \texttt{-v} 将您计算机上的文件夹绑定到容器内的某个路径。和端口映射相似，冒号之前的是在您计算机上的文件夹路径，而之后的则是容器内的路径。例如在 Windows 系统上，如果您使用了其他的文件夹存放模型文件，您可以像这样替换 \texttt{-v "\textbf{c:\textbackslash{}the-actual-folder}:/models"}。
\end{itemize}

\textbf{\texttt{llama.cpp}} 的选项：

\begin{itemize}
\item \texttt{-m} 告诉服务器应该使用哪个模型文件。这个 Docker 镜像自身不包含模型文件，我们使用刚刚映射在 \texttt{/models} 路径下的文件。

\item \texttt{-c} 设置上下文长度。更大的数值可以让模型读取更多输入，但对应的也会使用更多内存。在这个示例中，\texttt{32768} 代表 32K token。

\item \texttt{--port} 告诉服务器监听哪个端口。在本次工坊中，我们使用 \texttt{8080} 端口。
\end{itemize}

\section{工作原理}

我也仍在学习大语言模型，但会尽量用简单的话解释一些主要概念。

\subsection{llama.cpp}
\label{sec:llama.cpp}

机器学习领域里有三个关键的名词：模型、训练和推理。模型存放着系统学到了什么。训练指的是生成模型的过程。推理指的是使用模型产生输出的过程。

llama.cpp 是一个推理工具，但它并不是唯一的选择。其他可用的工具有 vLLM、LM Studio 以及 Ollama。

llama.cpp 创建之初的一个目标，是在不依赖 GPU 的情况下运行模型。这也是我们不需要特殊硬件的原因。之后，llama.cpp 也加入了对 GPU 和 NPU 的支持，比如 CUDA、Metal、Vulkan 和其他技术。

llama.cpp 提供了编译好的可执行文件以及 Docker 镜像。如果您无法使用 Docker，或者不希望使用 Docker，也可以从 \url{https://github.com/ggml-org/llama.cpp/releases} 下载最新版本。解压后，从命令行启动 \texttt{llama-server}。您可以使用在第 \ref{sec:run-llama.cpp} 节介绍过的 llama.cpp 选项。

\subsection{模型}
\label{sec:models}

这次工坊中我们使用的是 Qwen3-0.6B。Qwen（通义千问）是阿里云发布的开放权重语言模型家族。千问 3 发布于 2025 年，它有多个不同的模型大小，例如 0.6B 和 1.7B。0.6B 的含义是模型拥有 6 亿个参数。

简单来说，参数指的是模型里存放的数字。更大的模型拥有更多的参数，通常能力更强，但是运行时也需要更多的资源。

模型也有不同的架构。稠密（dense）模型在推理时会使用所有参数。混合专家模型（MoE，\textbf{Mixture of Experts}）包含许多专家部分，但每个 token 只会使用其中一部分。例如，\texttt{Qwen3.6-35B-A3B} 总共有 35B 参数，但每个 token 只会激活其中 3B。

非常大的开放权重模型同样存在。最近的例子包括 \texttt{Qwen3.8-2.4T-A95B}、\texttt{DeepSeek V4-Flash}、\texttt{GLM-5} 以及 \texttt{Kimi-K3}。了解这些模型是有用的，但如果您想在自己的计算机上运行模型，它们通常不是最合适的第一步。

有些模型也是多模态模型。例如，所有 Gemma 4 模型都支持文本、图像和视频输入，而 \texttt{E2B}、\texttt{E4B} 和 \texttt{12B} 还支持音频。

您可以通过浏览器访问 Hugging Face 下载模型文件。大模型通常由很多文件组成。Hugging Face 提供了一个名为 \texttt{hf} 的命令行工具来下载模型，您可以将这个过程理解成类似 \verb|git clone| 的模型下载方式。请查阅官方指南 \url{https://huggingface.co/docs/huggingface_hub/en/guides/cli}。

\subsection{GGUF}
\label{sec:gguf}

大多数原始模型采用 PyTorch 使用的格式存放，这些文件通常以 \texttt{.safetensors} 为扩展名。llama.cpp 使用了另一种格式，叫作 \texttt{GGUF}。llama.cpp 项目中提供了将模型转换为 GGUF 格式的脚本。

通常在格式转换后还有一步，叫量化（quantization）。原始模型通常使用高精度格式的数字，例如 32 位或者 16 位浮点型。量化使用更少的位来储存模型，比如它可以将 16 位的数字减少为 4 位。这个过程会减小模型文件，也可以加速推理，但代价是模型的准确性可能降低。

本次工坊中我们提供了三个模型文件：

\begin{itemize}
\item \texttt{Qwen3-0.6B-BF16.gguf}：未量化的版本。
\item \texttt{Qwen3-0.6B-UD-Q4\_K\_XL.gguf}：这个文件使用 4-bit 量化。在平衡文件大小和质量的时候，\texttt{Q4} 量化是一个常见的选项。\texttt{XL} 表示这种量化方式会使用较高精度保存更多的重要参数。另一个更常见的量化选择是 \texttt{Q4\_K\_M}。
\item \texttt{Qwen3-0.6B-UD-IQ1\_S.gguf}：这个文件使用 1-bit 量化。\texttt{IQ1\_S} 非常小，所以它使用更少的内存，但它的输出质量可能更差。
\end{itemize}

Hugging Face 上同样托管了很多已经转换为 GGUF 格式的模型。这意味着您通常不需要自己转换和量化模型。\texttt{ggml-org}\footnote{\url{https://huggingface.co/ggml-org}} 也发布了不少适用于 llama.cpp 的 GGUF 模型，例如 \texttt{gpt-oss-20b-GGUF}。\footnote{\url{https://huggingface.co/ggml-org/gpt-oss-20b-GGUF}}

其他的组织也会发布 GGUF 格式的模型。在本次工坊使用的模型文件名称中 \texttt{UD} 代表的是 \textbf{Unsloth Dynamic}。\footnote{\url{https://unsloth.ai/docs/basics/dynamic-3.0-ggufs}} Unsloth AI 在 Hugging Face 上发布了很多量化后的模型。您可能会在网上很多有关本地大模型的讨论中看到 UD 版本。

那么工坊结束后，您应该尝试哪个模型呢？我建议按照下面的流程：

\begin{enumerate}
\item 如果您有一台性能更强的计算机，可以先尝试中等大小的本地模型，例如 \texttt{Qwen3.8-27B}、\texttt{Qwen3.6-35B-A3B} 或者 \texttt{gemma-4-26B-A4B}。\footnote{根据 Gemma 4 模型卡的表 1，加载 4-bit \texttt{gemma-4-26B-A4B} 大约需要 14.4 GB 的 GPU 或 TPU 内存。同一张表也列出了其他模型大小和量化级别的内存估算，所以选择模型时值得参考。请查看 \url{https://ai.google.dev/gemma/docs/core/model_card_4}。} 请从量化后的 GGUF 文件开始。如果模型无法放入内存，可以降低上下文长度，或者使用更小的量化文件。

对于较大的模型，llama.cpp 的选项可能会带来明显差异。对于稠密模型，\texttt{-ngl} 控制有多少层会被放到 GPU 上运行。对于 MoE 模型，\texttt{--n-cpu-moe} 可以把一部分 MoE 权重保留在 CPU 内存里。这些选项可以帮助模型在有限的硬件上运行，但最佳数值取决于您的 GPU、显存、内存、模型大小、量化方式以及上下文长度。

如果您不知道从哪里开始，可以让语言模型根据您的硬件建议 llama.cpp 的设置。然后测试这些设置，观察内存和显存使用情况，并在可能的情况下调整设置，让更多工作交给 GPU。

\item 如果模型仍然太慢或者太大，可以尝试更小的模型。较小的模型可能需要更清楚的提示词，但它们仍然可以用于编程任务。例如，\texttt{Qwen3.5-9B-UD-Q4\_K\_XL.gguf} 的文件大小约为 6 GB，\texttt{gemma-4-E4B-it-UD-Q4\_K\_XL.gguf} 的文件大小约为 5 GB。\footnote{\texttt{it} 是 instruction-tuned 的缩写，表示这个模型经过了指令微调，更适合听懂并执行人的指令。}

\item 您也可以尝试混合使用不同的模型。例如，先用较大的模型讨论计划，再用较小的本地模型修改代码。有些工具也提供云端模型，所以您可以使用更大的模型，而不需要完全在自己的计算机上运行它们。
\end{enumerate}

\subsection{OpenAI 兼容的接口}
\label{sec:api}

Pi 能和 llama.cpp 一起工作，原因是 llama.cpp 实现了 OpenAI 兼容的接口，而配置文件 \texttt{models.json} 告诉 Pi 如何连接到模型服务器。您可以在编辑器中打开 \texttt{models.json} 文件查看配置。您也可以访问 \url{https://pi.dev/docs/latest/models} 查看完整的配置说明。这里我们只看几个比较重要的设置：

\begin{itemize}
\item \texttt{api}：OpenAI 兼容的 API 并不是唯一被广泛使用的格式。如果您希望让 Pi 使用其他接口格式，请查阅 Pi 的文档。
\item \texttt{baseUrl}：本次工坊中 llama.cpp 和 Pi 运行在同一台计算机上的不同容器内。如果您使用了不同的方式运行 llama.cpp 或者 Pi，您很可能需要更新这个 URL。
\item \texttt{contextWindow} 以及 \texttt{maxTokens}：这些设置取决于您使用的模型，以及您如何运行模型。请依据实际情况调整这些数值。
\end{itemize}

OpenAI 兼容的接口让其他工具也可以用相似的方式连接到推理服务器。OpenCode、Copilot 以及 Qwen Code 等智能体工具也可以用类似的配置方式和 llama.cpp 协作。

也有一些不是专门用于编程的工具：

\begin{itemize}
\item Open WebUI：一个类似 ChatGPT 界面的、通用的 Web 界面。
\item AnythingLLM：带有 RAG 功能的知识助理。\footnote{RAG 指检索增强生成，retrieval-augmented generation。}
\item Langflow：一个开源的、用于构建 AI 工作流的低代码平台。
\item TradingAgents: 多智能体金融交易框架。\footnote{该项目仅供研究目的，不构成金融、投资或者交易建议。参见 \url{https://github.com/TauricResearch/TradingAgents}。}
\end{itemize}

因为这些工具我大多还没用过，因此本节仅仅简要介绍。

\subsection{Docker}
\label{sec:Docker}

最后让我们来聊聊在运行本地语言模型的时候，Docker 为什么依然可能有用。

有时候您可能需要在他人维护的代码仓库里做些改动。它可能使用了您不熟悉的编程语言或者构建系统。您并不确定在运行过程中代码都会做些什么。这种情况下，Docker 可以提供隔离的环境。您可以仅将需要使用的文件夹映射到容器中，这可以大大降低这些代码修改或者损坏您计算机上其他文件的风险。

在使用智能体工具时，模型有可能会返回错误的、甚至危险的指令。例如模型可能让智能体删除项目文件夹以外的文件。将智能体运行在容器内可以限制智能体能访问的文件范围。

Docker 的隔离机制很有用，但也不是绝对安全。不过关于 Docker 安全使用的讨论超出了本次工坊的范畴，我们可以在 \texttt{Devs \& Lattes} 继续讨论。

\section{小结}

在本次工坊中，您学到了最基本的流程：下载模型、借助推理工具运行模型，并将模型接入到一个应用程序。

llama.cpp 只是在本地运行模型的方法之一。您也可以尝试其他工具，比如 LM Studio 或者 Ollama。有些工具提供了更友好的用户界面，可能比命令行更容易上手。
